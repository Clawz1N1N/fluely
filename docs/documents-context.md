# Attachments and context

Activate the chat with the configured interaction shortcut, choose **Attach files**, preview the extracted text or image, then send your question. Documents are supplied as reference data, not system instructions. The full original attachment and extracted text are retained in the session archive.

You can also drop files anywhere in the chat while **Interaction** is active. Passive chat ignores drops. Windows native drops use short-lived, one-use grants from actual OS drop events; the reader accepts a grant ID rather than arbitrary file paths. File picker and drop intake share size/count/format checks and cancel stale work when the session changes. Conversation and dashboard history show document filenames with extensions instead of extracted XML/text; selecting an unsent attachment still opens its optional preview. The complete source is sent for inference and retained in the archive.

Supported readers cover UTF-8/UTF-16 text, Markdown, CSV/TSV, JSON/XML/HTML/log files, DOCX, XLSX, PPTX, ODT, ODS, ODP and text-bearing PDF files. Images can be sent to an image-capable reasoning model or described by the configured vision model first. Scanned PDFs need page images/OCR; encrypted or unsupported files show a specific error. DOC, XLS, PPT and RTF conversion requires an installed LibreOffice. Fluely does not replace an Office editor or promise to preserve document formatting when extracting text.

Limits are eight attachments, 16 MB per file, 32 MB combined original data and 200,000 extracted characters across documents. Office packages also have decompression/XML limits. Parsing runs in a cancellable worker. Modern document readers and PDF fonts/CMaps are bundled locally; no document is uploaded until the user sends it. Cloud inference then receives the extracted content/images according to the selected provider.

The chat shows context tokens, the configured context window and a percentage including the reserved output allowance. `≈` identifies an estimate using a maintained multilingual BPE tokenizer with a margin; different models have different vocabularies. Provider-reported input usage is used for the completed request when available. The idle view estimates the current saved conversation rather than presenting an old request count as current usage.

At 90% occupancy, older turns are summarized through the selected reasoning provider while recent exchanges remain verbatim. Summary requests obey that model's request/token quotas and are cancellable. The summary is saved with its boundary in the session; original events and files remain available in history. If the current input and recent turns alone exceed the model window, Fluely asks for a smaller document section, fewer reserved output tokens or a larger-context model instead of silently discarding the input.
