# Fluely: уточнення 13 жовтня

Дозвіл: користувач доручив продовжити всі попередні пункти та опублікувати код у власному форку. Поточні зміни зберігаємо; конфігурації реального профілю не використовуємо для тестів.

## Дизайн

- Реєстр залишається списком моделей для ранжування та резервування запитів. Моделі отримують provider_id, display_name, credential_id, context_window, max_output_tokens та supports_audio. API-ключ належить окремому credential_id у системному сховищі; кілька моделей посилаються на один ключ, кілька ключів одного провайдера незалежні.
- Єдиний редактор провайдерів замінює cURL у налаштуваннях і Dev Space. Вбудовані URL приховані; Other використовує окремі поля. Вибір моделей працює у діалозі з пошуком, чекбоксами, undo/redo, all/none і скасуванням без запису. Пакет моделей публікується атомарно після перевірки секрету.
- Discovery адаптери використовують офіційні models API і пагінацію. Відомі metadata імпортуються без вгадування можливостей за назвою; невідомі можливості та ліміти виставляються вручну.
- GGUF ASR додається тільки через рушій, який реально підтримує відповідну архітектуру; Whisper і Windows STT залишаються окремими.
- Два методи зору мають явний вибір і модель тільки з supports_images. Другий метод визначається після читання TheiaVision/VDLM; відмінності, залежності та обмеження описуються чесно.
- Сон зупиняє мікрофон, скріншоти та ручні запити. Системне аудіо продовжує STT і запити з окремою інструкцією. Кодовий маркер парситься через межі потокових фрагментів; сигнал відтворюється на обраному пристрої.

## Виконання

1. Provider schema/discovery/selection tests, редактор і заміна legacy brain UI — root.
2. Сумісний GGUF ASR, керований запуск і налаштування — local engines agent.
3. Сон, native output audio та Audio settings — integration agent.
4. Дослідження і реалізація альтернативного зору — vision agent.
5. Інтеграція команд, повні uk/ru/en переклади, перевірка міграцій і запуск усіх перевірок — root.
6. Послідовна збірка, native UI/inference smoke у тимчасовому профілі, README і звіт, GitHub fast-forward публікація без force — root.

## Докази

Тестуємо багатосторінковий discovery, неповні метадані, відміну вибору, історію виділень, належність ключів, атомарний запис, ліміти запитів; реальні native режими і рушії. Стан попереднього autostart тесту: ERROR_ACCESS_DENIED при записі власного тестового Run — потрібна діагностика, повне проходження не заявлене.
